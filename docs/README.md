# OctoAcme Project Management Docs

OctoAcme uses an iterative project lifecycle to move work from initiation through planning, execution, release, and retrospective. Initiation validates the business need, success measures, stakeholders, risks, and resources; planning turns approved work into a prioritized backlog with acceptance criteria, estimates, dependencies, milestones, and a Definition of Done. Teams track delivery on a project board, build and review small increments, prepare releases with smoke tests and rollback plans, and verify deployments before capturing lessons learned.

The Project Manager coordinates schedules, risks, dependencies, and communications; the Product Manager defines outcomes, success measures, and priorities. Developers implement and test the work, QA/Testing validates acceptance and quality, and stakeholders provide input and approvals. Regular standups, delivery syncs, demos, and stakeholder updates keep progress visible. Teams maintain a risk register and escalate blockers from team triage through the PM and Product Lead to the sponsor when needed.

Quality is part of the full workflow: planning defines acceptance criteria and the Definition of Done; development uses unit tests and applicable integration tests; CI runs automated tests, linting, and security scans; and critical flows receive pre-release smoke tests. Pull requests should be small, link to issues, include acceptance criteria, and receive at least one approval or follow the team's policy. Manual QA and post-deployment checks are used where appropriate.
